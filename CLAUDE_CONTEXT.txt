## 9.1 LOCATOR — QUY TẮC CHỌN ĐÚNG LOẠI
--------------------------------------------------------

THỨ TỰ ƯU TIÊN:
1. id (resource-id)     → ổn định nhất, nhanh nhất
   ("id", "com.zing.mp3:id/tên_element")

2. accessibility id     → dùng khi không có resource-id
   ("accessibility id", "tên_accessible")

3. xpath theo text      → dùng khi cần tìm theo nội dung
   ("xpath", "//android.widget.TextView[@text='Khám phá']")

4. xpath theo index     → dùng khi nhiều element cùng resource-id
   ("xpath", "(//android.widget.ImageView[@resource-id='com.zing.mp3:id/icon'])[2]")

QUY TẮC BẮT BUỘC:
- Bên trong xpath LUÔN dùng dấu ' (nháy đơn), KHÔNG dùng " (nháy kép)
  ĐÚNG:  ("xpath", "//element[@resource-id='com.zing.mp3:id/icon']")
  SAI:   ("xpath", "//element[@resource-id="com.zing.mp3:id/icon"]")  ← SyntaxError

- Khi dùng id: KHÔNG có dấu // ở đầu
  ĐÚNG:  ("id", "com.zing.mp3:id/btn_play")
  SAI:   ("id", "//android...[@resource-id='com.zing.mp3:id/btn_play']")  ← dùng sai type

- KHÔNG dùng xpath quá dài (dễ vỡ khi app update UI)
  SAI:  //android.widget.FrameLayout[1]/android.widget.LinearLayout[2]/...

## 9.2 THỜI GIAN CHỜ — DÙNG ĐÚNG HÀM
--------------------------------------------------------

CÁC HÀM WAIT (ưu tiên dùng):
- page.wait_and_tap(locator)          → chờ clickable rồi mới tap
- page.wait_for_visible(locator)      → chờ hiển thị rồi mới dùng
- driver.implicitly_wait(10)          → đã set sẵn trong conftest.py

time.sleep() — CHỈ dùng khi:
- Chờ animation chuyển màn hình: time.sleep(1) hoặc time.sleep(2)
- Chờ kết quả tìm kiếm load: time.sleep(2)
- KHÔNG dùng time.sleep > 3 giây

THỨ TỰ ĐÚNG:
  page.wait_and_tap(BUTTON)    # tap rồi
  time.sleep(2)                # chờ màn hình mới load xong
  assert page.is_visible(...)  # kiểm tra kết quả

KHÔNG làm:
  page.tap(BUTTON)             # tap không chờ → dễ fail
  assert page.is_visible(...)  # kiểm tra ngay → chưa load xong

## 9.3 XỬ LÝ POPUP & QUẢNG CÁO
--------------------------------------------------------

NGUYÊN TẮC:
- conftest.py đã có dismiss_popup() — tự chạy trước mỗi test

- Nếu popup xuất hiện GIỮA test: thêm try/except xử lý tại chỗ

CÁCH XỬ LÝ POPUP GIỮA TEST:
  try:
      driver.find_element("id", "com.zing.mp3:id/btn_close").click()
      time.sleep(0.5)
  except Exception:
      pass  # không có popup → bỏ qua, tiếp tục test

KHÔNG làm:
  assert không có popup  ← làm fail test khi không có popup
  time.sleep(5) chờ popup tự tắt  ← lãng phí thời gian

THÊM POPUP MỚI VÀO conftest.py:
  Tìm hàm dismiss_popup() → thêm resource-id mới vào danh sách popup_ids

## 9.4 TRÁNH FLAKY TEST
--------------------------------------------------------

CÁC LỖI HAY GẶP VÀ CÁCH TRÁNH:

1. TimeoutException
   Nguyên nhân: locator sai hoặc element chưa load
   Fix: dùng Appium Inspector lấy đúng locator
        tăng timeout: page.wait_and_tap(locator, timeout=15)

2. NoSuchElementError
   Nguyên nhân: element không tồn tại trên màn hình hiện tại
   Fix: kiểm tra app đang ở đúng màn hình chưa
        thêm time.sleep(2) sau khi chuyển màn hình

3. SyntaxError: unterminated string literal
   Nguyên nhân: thiếu dấu " đóng trong locator
   Fix: kiểm tra cặp nháy trong android_locators.py

4. SyntaxError: invalid syntax / perhaps you forgot a comma
   Nguyên nhân: dùng " bên trong xpath string
   Fix: đổi attribute trong xpath thành dấu '

5. Element bị che (click không được)
   Nguyên nhân: element bị element khác phủ lên
   Fix: thêm scroll trước khi tap
        page.scroll_down() rồi wait_and_tap

6. Test phụ thuộc nhau
   Nguyên nhân: test sau cần state từ test trước
   Fix: mỗi test TỰ điều hướng đến màn hình cần test
        conftest.py đã reset về Home trước mỗi test

7. ModuleNotFoundError: appium
   Nguyên nhân: chưa cài trong .venv của PyCharm
   Fix: pip install -r requirements.txt trong Terminal PyCharm

## 9.5 BUGS ĐÃ FIX — KHÔNG LÀM LẠI
--------------------------------------------------------

BUG 1: Session init bị treo (hang) sau khi UiAutomator2 crash
   Triệu chứng: webdriver.Remote() treo mãi không tạo được session
   Nguyên nhân: UiAutomator2 server còn sót từ lần crash trước
   Fix đã áp dụng: conftest.py gọi _cleanup_uiautomator2() trước VÀ sau session
     → force-stop cả "io.appium.uiautomator2.server" và ".server.test"
   KHÔNG xóa hoặc bỏ qua _cleanup_uiautomator2() call trong conftest.py

BUG 2: Test chạy chậm (~10-20 giây/bước) trên real device
   Nguyên nhân gốc:
   a) driver.implicitly_wait(10) → gây double-wait 10s mỗi lần find_element thất bại
   b) appActivity = SplashActivity → mỗi session phải chờ splash screen
   c) BOTTOM_NAV_* dùng XPATH FrameLayout → is_enabled()=false → element_to_be_clickable luôn timeout
   Fix đã áp dụng:
   - implicitly_wait(0) — KHÔNG đổi lại về giá trị khác
   - appActivity = MainScreenActivity — KHÔNG dùng SplashActivity
   - BOTTOM_NAV_* dùng ANDROID_UIAUTOMATOR tvLabel.text() — KHÔNG dùng XPATH FrameLayout
   - Performance caps trong android_config.py: skipServerInstallation, skipDeviceInitialization,
     skipUnlock, disableWindowAnimation

BUG 3: UiAutomator2 crash / socket hang up khi tap Category Tab
   Triệu chứng: instrumentation OOM crash, socket hang up
   Nguyên nhân: flat tvTitle.text() selector khớp hàng chục element bài hát/playlist trên màn hình
   Fix đã áp dụng: TAB_* dùng childSelector scoped vào rvCategory
     → chỉ tìm trong 4 tab, không scan toàn bộ UI tree
   VÍ DỤ ĐÚNG:
     TAB_CHO_BAN = (AppiumBy.ANDROID_UIAUTOMATOR,
         'new UiSelector().resourceId("com.zing.mp3:id/rvCategory")'
         '.childSelector(new UiSelector().resourceId("com.zing.mp3:id/tvTitle").text("Cho bạn"))')
   KHÔNG dùng: UiSelector().text("Cho bạn") không có childSelector → crash

BUG 4: Bottom nav click fail sau khi Player đang mở
   Triệu chứng: reset_to_home không điều hướng được → test tiếp theo fail ngay bước đầu
   Nguyên nhân: full Player che khuất bottom nav, presence_of_element_located pass nhưng click không có tác dụng
   Fix đã áp dụng trong _navigate_to_home():
     1. activate_app() — đảm bảo app ở foreground
     2. Minimize full Player nếu đang mở (kiểm tra PLAY_PAUSE_BTN = btnPlay)
     3. dismiss_player_overlays()
     4. WebDriverWait element_to_be_clickable (KHÔNG dùng presence_of_element_located)
   KHÔNG đổi lại về presence_of_element_located

BUG 5: minimize_player() dùng ACCESSIBILITY_ID "Di chuyển lên" — unreliable
   Triệu chứng: tap MINIMIZE_BTN đôi khi không có tác dụng (accessibility label thay đổi theo theme)
   Fix đã áp dụng: minimize_player() trong BasePage dùng driver.back()
   KHÔNG dùng wait_and_tap(AndroidPlayerLocators.MINIMIZE_BTN) để minimize player

BUG 6: dismiss_player_overlays() bỏ sót popup xuất hiện muộn
   Triệu chứng: POPUP_SKIP_BTN (btnNegative) có nhưng is_visible() trả False vì sheet chưa render xong
   Fix đã áp dụng: dùng is_visible_with_wait(POPUP_SKIP_BTN, timeout=5) thay vì is_visible()
   KHÔNG dùng is_visible() (không có wait) để check popup trong dismiss_player_overlays()

## 9.6 QUY TẮC LOCATOR — PHÂN BIỆT FULL PLAYER vs MINI PLAYER
--------------------------------------------------------

FULL PLAYER (màn hình phát nhạc đầy đủ):
  PLAY_PAUSE_BTN = ("id", "com.zing.mp3:id/btnPlay")        ← tên resource-id là "btnPlay"
  MINIMIZE_BTN   = ("accessibility id", "Di chuyển lên")    ← KHÔNG dùng, dùng driver.back() thay thế

MINI PLAYER (thanh nhỏ ở bottom):
  MINI_PLAYER           = ("id", "com.zing.mp3:id/playbarContainer")
  MINI_PLAYER_PLAY_PAUSE = ("id", "com.zing.mp3:id/btnPlayPause")  ← tên resource-id là "btnPlayPause"

PHÂN BIỆT:
  - Full Player đang mở ↔ page.is_visible(AndroidPlayerLocators.PLAY_PAUSE_BTN) trả True
  - "btnPlay" chỉ tồn tại trên full Player — dùng để detect xem full Player có đang hiển thị không
  - "btnPlayPause" chỉ tồn tại trên mini player — dùng để tap play/pause từ mini player

## LOGIN STATE — MARKERS BẮT BUỘC
--------------------------------------------------------

Mỗi test case PHẢI có đúng 1 hoặc nhiều login state marker.
conftest.py tự động login/logout đúng tài khoản trước mỗi test.

5 TRẠNG THÁI LOGIN:
  @pytest.mark.non_login  → chưa đăng nhập
  @pytest.mark.free       → tài khoản Free (có quảng cáo, không tải offline)
  @pytest.mark.plus       → tài khoản Plus (không quảng cáo, không tải offline)
  @pytest.mark.premium    → tài khoản Premium (full tính năng, tải offline)
  @pytest.mark.offline    → không có mạng

QUY TẮC CHỌN MARKER:
- Test kiểm tra giới hạn của Non-login    → @pytest.mark.non_login
- Test kiểm tra quảng cáo                → @pytest.mark.free
- Test kiểm tra tải nhạc offline          → @pytest.mark.premium
- Test chạy được cho mọi user đã login    → @pytest.mark.free + @pytest.mark.plus + @pytest.mark.premium
- Test chạy được cho tất cả              → thêm cả @pytest.mark.non_login

BẢNG QUYỀN TÍNH NĂNG:
  Tính năng                | non_login | free | plus | premium
  Xem danh sách / tìm kiếm | ✅        | ✅   | ✅   | ✅
  Nghe thử 30 giây         | ✅        | —    | —    | —
  Nghe full bài            | —         | ✅   | ✅   | ✅
  Nghe không quảng cáo     | —         | —    | ✅   | ✅
  Tạo playlist             | —         | ✅   | ✅   | ✅
  Tải nhạc offline         | —         | —    | —    | ✅
  Nghe lossless            | —         | —    | —    | ✅

FORMAT BẮT BUỘC KHI VIẾT TEST:
  @pytest.mark.LOGINSTATE         ← login state (bắt buộc)
  @pytest.mark.smoke/regression   ← mức độ test (bắt buộc)
  @allure.title("STATE: Mô tả")   ← title có tên state ở đầu

VÍ DỤ ĐÚNG:
  @pytest.mark.premium
  @pytest.mark.smoke
  @allure.title("Premium: Tải nhạc offline thành công")
  def test_premium_download(self, driver):
      ...

  @pytest.mark.free
  @pytest.mark.plus
  @pytest.mark.regression
  @allure.title("Free/Plus: Tạo playlist mới")
  def test_create_playlist(self, driver):
      ...

  @pytest.mark.non_login
  @pytest.mark.smoke
  @allure.title("Non-login: Chỉ nghe thử 30 giây")
  def test_preview_only(self, driver):
      ...

CÁCH CHẠY THEO TRẠNG THÁI:
  pytest tests/ -m non_login --platform=android -v
  pytest tests/ -m free --platform=android -v
  pytest tests/ -m premium --platform=android -v
  pytest tests/ -m "free or plus" --platform=android -v
  pytest tests/ -m "smoke and premium" --platform=android -v

## TEMPLATE TEST CASE ĐẦY ĐỦ VỚI LOGIN STATE

import allure, time, pytest
from pages.base_page import BasePage
from locators.android_locators import AndroidHomeLocators

@allure.feature("Tên màn hình")
class TestTenManHinh:

    @pytest.mark.LOGINSTATE        # non_login / free / plus / premium / offline
    @pytest.mark.smoke             # smoke / regression
    @allure.story("Nhóm chức năng")
    @allure.title("LOGINSTATE: Mô tả test case ngắn gọn")
    def test_ten_ro_rang(self, driver):
        page = BasePage(driver)
        # KHÔNG mở app, KHÔNG login/logout — conftest.py đã lo

        with allure.step("Bước 1: thao tác"):
            page.wait_and_tap(AndroidHomeLocators.TEN_LOCATOR)
            time.sleep(1)

        with allure.step("Bước 2: kiểm tra"):
            assert page.is_visible(AndroidHomeLocators.KET_QUA), \
                "Thông báo lỗi rõ ràng"
